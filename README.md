# AI Dev Harness — WinUI 3 Local + Hybrid AI Prototype Pack 🧰

A **skunkworks** prototype pack for jump-starting **on-device** and **hybrid**
AI demos on Windows. One repo, one interactive generator (`new-demo.ps1`),
two reference harnesses, ten shared building blocks. Built around the
**native Foundry Local C# SDK** so every demo ships as a Store-ready
WinUI 3 / .NET 9 desktop app from day one.

Optimised for **Intel Core Ultra (AI Boost NPU + Arc iGPU)** with **Phi-4-mini**
as the default small model. **Snapdragon X / QNN** runtime is auto-detected
(falls back to **Qwen 2.5 3B** as the small SLM). **AMD Ryzen** is detected
and treated as x64-class generic.

Built around a single thesis: **the work that actually has to be on the
frontier should be on the frontier; everything else belongs on the device.**
A live cost ticker in every generated demo compares **hybrid actual vs
cloud-only equivalent** in real time as you walk the tabs — so the savings
number tells itself.

A deterministic **Mock mode** ships in every demo as a live-presentation
safety net — flip it on before going on stage and no chat tab ever
dead-ends, even if Foundry Local or the cloud endpoint flakes mid-demo.

## What's in the box

| Component | Purpose |
|---|---|
| **`new-demo.ps1`** | Interactive generator. Detects your silicon, asks ~9 questions, stamps out a customised demo solution under `demos\<name>\` and (optionally) creates a GitHub repo for it. |
| **`src/Shared`** | Class library with 10 reusable building blocks: Foundry Local client, silicon detector, cost log + ticker, streaming chat view, theming, settings + Mock toggle, demo-data loader, PII scanner, audit logger, diagnostics panel. |
| **`src/LocalAIDevHarness`** | Reference Local-only solution. The generator copies this when you pick "Local". |
| **`src/HybridAIDevHarness`** | Reference Hybrid solution. Adds an `ICloudChatClient` (Azure OpenAI v2 + Azure.AI.Inference + deterministic frontier mock) and a `HybridRouter`. |
| **`.github/workflows`** | CI builds both solutions on every push; `store-release.yml` packages and signs MSIX bundles for Partner Center. |

## UX flow (what the generator asks)

See [`docs/UX-FLOW.md`](docs/UX-FLOW.md) for the full presenter script.
Short version — 9 prompts, all with sensible defaults:

1. Demo name
2. Local vs Hybrid
3. Build architecture (silicon-aware default: ARM64 on Snapdragon, x64 otherwise)
4. Industry focus (10 choices + N/A)
5. Modality (text / vision / both)
6. Foundry Local text model alias (N/A → silicon-aware default)
7. (if vision) Foundry Local vision model alias
8. Mock mode default on/off
9. Use cases — one per line, or `N/A` to let the generator pick from the industry catalogue

Then: optional git init + optional `gh repo create`.


## Mock mode (live-demo safety net)

Every harness and every generated demo ships with a deterministic Mock
client. Flip it on in **Settings → Mock mode**, or set
`AppHost.Settings.UseMock = true` in code. While Mock is on:

- No call leaves the process.
- Every chat tab streams a deterministic stub reply.
- A **🎭 MOCK MODE** badge appears in `StreamingChatView` so the presenter
  always knows which path is live.
- `CostLog` still records events (route `mock`, USD 0) so the ticker keeps
  ticking.

This is the same pattern used in the earlier `surface-npu-demo` and
`Zava-Medical-Local-AI-Showcase` projects — added here so the hybrid
generator inherits the safety net by default.

## Silicon-aware build choice

`new-demo.ps1` reads `Win32_Processor` and recommends:

| Silicon | Default arch | Default model alias |
|---|---|---|
| Intel Core Ultra | x64 | `phi-4-mini` |
| Qualcomm Snapdragon X / Oryon | ARM64 | `qwen2.5-3b` |
| AMD Ryzen | x64 | `phi-4-mini` |
| Unknown / other | x64 | `phi-4-mini` |

Override per-demo by passing `-Architecture both` to produce ARM64 **and**
x64 publishes from the same source tree (or by editing
`<RuntimeIdentifiers>` in the generated csproj after the fact).

## Open items

- Final model picks per silicon will track whatever the Foundry catalogue
  ships; the `phi-4-mini` / `qwen2.5-3b` defaults are working assumptions.
- Optional real Azure OpenAI / Azure AI Foundry Inference paths are wired
  but ship configured against `MockFrontierClient` by default; flip them on
  via `AppHost.ConfigureAzureOpenAI(...)` once credentials are in Key Vault.
- The Partner Center submit step in `store-release.yml` is a stub; wire
  StoreBroker.NET or `microsoft/msstore-cli` once the publisher identity
  exists.
- Vision pages generated by the harness ship as a stub that picks an image
  and previews it; wire your preferred vision-model client into `OnPick`.
